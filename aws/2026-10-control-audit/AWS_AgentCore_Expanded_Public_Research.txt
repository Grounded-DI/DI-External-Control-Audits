03 / Tool calls, discovery and resources
 AWS documents policy evaluation for MCP tool invocations. The same documentation says prompt and
 resource methods are allowed regardless of policy mode. This is a defined surface of policy evaluation; it
 does not prove access without authentication or that other controls are absent. [S1]

 Tool listing is a meta action using partial authorization: a tool may appear where some invocation could
 be allowed, without promising authorization for every set of arguments. [S1]

 Counterargument: target authorization, identity controls and network restrictions can operate outside the
 policy engine. To settle actual exposure, measure each route in an authorized isolated deployment and
 record each additional control and target response.

04 / Enforcement modes and authority
 AWS describes engine ENFORCE as applying authorization decisions and engine LOG_ONLY as evaluating
 and logging without enforcing them. An individual policy can also be LOG_ONLY in an enforcing engine
 while other active policies remain effective. [S2–S3]

 AWS states that UpdateGateway permission can change the engine mode or remove the association. This
 is a documented administrative capability, not evidence that an unauthorized user changed the setting.
 [S2]

 Decisive test: capture effective IAM permissions, Gateway configuration, policy state and change events;
 compare the same synthetic request under each authorized mode. Record decision telemetry and
 independently observed target invocation.

06 / Cedar source: erroring policies
 The pinned Cedar authorizer records evaluation errors and, in its default skip mode, treats an erroring
 policy as not satisfied. Its partial-response decision logic uses satisfied permits and forbids. [S7–S8]

 A narrow hypothesis follows: where a forbid errors but a separate permit is satisfied, the failed forbid may
 not deny and the diagnostic needs attention. This is source analysis, not an executed Cedar result. It is
 not evidence of a hosted AgentCore bypass. [S7–S8]

 The eight proposed Cedar cases were not run: the environment lacked a discoverable Cedar executable
 and Rust/Cargo toolchain. Exact executable fixtures remained to be finalized and frozen. A real Cedar
 test would not by itself prove managed Gateway behavior.
