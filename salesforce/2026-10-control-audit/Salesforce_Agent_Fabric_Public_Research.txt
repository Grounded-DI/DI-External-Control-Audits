F1 | The budget ceiling is not a zero-overshoot
guarantee
Control / promise. The Salesforce announcement describes hard Model Wallet spending limits that stop
requests before costs exceed a budget. The pinned MuleSoft wallet instructions say a model proxy blocks
further requests to a provider after the budget is reached, but describe enforcement as approximate rather
than a real-time hard cutoff, allowing a brief exceedance. The pinned cost guide repeats that qualification.
[S01–S03]

Documented discrepancy. A hard block at some point after a metering threshold is not equivalent to a
mathematically non-exceedable ceiling. Both can be called a limit in operational speech, but they imply
different guarantees to a budget owner. The documents use the same Model Wallet capability name. The
broader announcement language cannot by itself establish a strict real-time cutoff.

What the documents do not quantify. Neither a bound on allowed overshoot nor the treatment of
simultaneous requests, already-admitted calls, delayed usage settlement, model-specific price revisions,
failed/retried requests or third-party billing reconciliation is established in the reviewed excerpts. No actual
model request, invoice or budget event was generated in this audit.

The strongest charitable reading is that hard means eventually enforced by a deny decision while the technical
documentation discloses an accounting delay. That could be Salesforce's intended meaning. It does not satisfy
a reader who interprets hard as no post-threshold spend, and it leaves an enterprise procurement requirement
unresolved.

The correct engineering question is not whether the word hard is rhetorically defensible; it is whether an
organization can compute its maximum possible financial exposure before submitting work. That requires
observable admission, usage settlement and blocking semantics.

F3 | The kill-switch stopping boundary
Control / promise. The pinned operational instructions describe two cooperating policies applied to protected
model proxies: Rogue Agent Detection flags an agent for review, and Agent Kill Switch blocks the identified
agent at those proxies after containment. The instructions require validated JWT claims and matching identity
selectors. [S05]

The live Agent Governance page makes a materially broader representation: the kill switch acts across
network, credential and identity layers simultaneously, cutting the agent off from what it could reach. The
operational guide reviewed in this audit does not trace every mechanism needed for that outcome. [S06]

Documented versus unresolved. The named proxy policy is an observable configuration and access-control
surface in the documentation. It does not by itself establish that a direct API route, a second proxy without the
policy, a cached credential, a queued worker, an in-flight tool call or an already completed irreversible side
effect is interrupted. Other control layers may exist; the audit did not test or disprove them.

Timing is essential. Blocking the next model request can be successful while an already authorized purchase,
message or file mutation completes downstream. Consequently, an enterprise definition of kill must name the
exact stages it stops: admission, execution, credential use, retries, scheduled work and external side effects.

F4 | Detection, identity and policy placement
Control / promise. The policy instructions require an Agent Identity Selector based on validated JWT claims,
the same selector on detection and kill-switch policies, and placement of both policies on each model proxy
intended for protection. The guide explicitly says that a detector with no rules forwards requests without
detecting anything. [S05]

That no-rule behavior is not itself a defect. It is a concrete configuration state with no detection. A production
assurance program that merely confirms installation of a policy, rather than active rules and end-to-end
identity consistency, can therefore report nominal coverage without demonstrating a working detector.

Observed boundary. No UI form, claim parser, malformed JWT, policy compiler, deployment-time check,
detector inference service or quarantine persistence system was exercised. The guide states that detection
adds inference calls, which creates an additional operational dependency and potential incremental cost.
Whether the UI prevents empty rules or selector mismatches was not measured.

Strongest defense. Administrators may deliberately configure a nonblocking detector; deployment tooling
may constrain mismatched selectors or empty policies. The documented behavior should be judged against
the chosen organizational policy, not against an invented universal requirement that every configured
detector block requests.

Control / promise. The pinned generic Terraform policy resource describes validation of known policy

along the Create and Update paths; that file does not visibly provide a ValidateConfig or ModifyPlan method.

Helper contract and code. The pinned ValidatePolicyConfiguration helper returns no validation errors

Fresh local recheck. Six supplied audit-authored Go tests passed against the unchanged pinned helper with
an inert client stub. Three additional isolated cases, authored separately from the four supplied files and rerun
for this publication review, also passed: a value above a declared maximum, a value outside a declared string
enum, and an element outside a declared array enum produced no helper errors. These outcomes concern
that function, not a deployed policy.

F6 | Audit-log visibility is not retention proof
Control / promise. The pinned operational guide says the Security page presents flagged and reviewed
agents from a 90-day lookback. It also describes audit records for quarantine and reactivation actions,
including agent identifier, initiating user, timestamp and environment. [S05]

Unresolved boundary. A security UI time window is not a retention SLA for the underlying audit store. The
reviewed sources do not establish whether evidence is append-only, independently tamper-evident, available
through an export API, or preserved through network partition, retry, backend outage or administrative
deletion. Nor do they show the time ordering of every detector decision, proxy deny and external side effect.

The strongest alternative is that separate logging products, organization-level retention settings or contracts
may provide these guarantees. Because those sources were outside this audit, the correct disposition is a
missing evidence requirement, not an assertion that logs are discarded after 90 days.

Decisive test — NOT EXECUTED. Quarantine and restore a synthetic identity while recording causal event
IDs and policy version. Restart the affected telemetry component, interrupt the sink and restore it. Compare
records in the UI, query/export interfaces and durable store after the UI lookback. Verify event completeness,
order, privilege-based deletion, retention and disposition.

  F6 DISPOSITION
  UNRESOLVED. The 90-day UI lookback and named action fields are documented. Retention duration,
  immutability, completeness and failure behavior are not established.

  The original extracted-package verifier cannot by itself establish exact file membership for every

Engineering conclusions and open questions
1. The budget conflict is the clearest public claim to resolve. A buyer requiring a strict non-exceedable
dollar ceiling cannot infer that guarantee from the documentation reviewed. The limit may be operationally
effective; its permitted overshoot is not bounded by the cited sources. [S01–S04]

2. A kill switch must be defined by its reach. The documented operational policy blocks quarantined
identities at protected model proxies. Broader simultaneous network, credential and identity containment
requires architectural and in-flight evidence not obtained here. The report preserves both statements rather
than treating the operational guide as proof against broader layers. [S05–S06]

3. Configuration completeness is an enforcement precondition. Missing prices can produce zero
recorded dollar spend; a no-rule detector can detect nothing; identity selectors and policy placement
determine proxy coverage. These are documented choices with important deployment consequences, not
observed customer incidents. [S02–S05]

4. Infrastructure tooling is not the product runtime. The pinned Terraform helper checks fewer
properties than its field metadata declares, and the local Go tests reproduce that narrow fact. No inference to
hosted acceptance, policy bypass or plan-time behavior is warranted. [S07–S09]

unlisted nested manifest file while rejecting ordinary tampering. Reporting that result, and separately
validating the actual supplied archive inventory, preserves the distinction between a useful control and a
complete guarantee.
